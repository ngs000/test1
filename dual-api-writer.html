Geração

O piso força continuações mesmo quando o modelo decide parar sozinho (finish_reason "stop") antes de atingir esse número de palavras — é a causa mais comum de respostas curtas apesar de max_tokens alto. Ex.: 5000 para bater o mínimo do teu sistema de escrita.

Com um plano de cenas (beats), o capítulo segue uma estrutura definida antes de escrever — ajuda capítulos longos a não se perderem nem encherem chouriços. O plano fica na indicação e é usado também em regenerar, variantes e continuar.

Com streaming, conta o tempo sem receber dados; sem streaming, o tempo total do pedido. Se a ligação cair a meio de um stream, o texto recebido é mantido e a geração continua a partir daí.

"Automático" não envia o campo de thinking/reasoning — o provider usa o próprio default. Cada continuação reenvia o contexto + o texto parcial e pede para retomar exatamente onde parou.

Já vem preenchido para usar com o server.py/start.bat incluídos. Se a API der "Failed to fetch" / erro de CORS, confirma que o server.py está a correr. Com o campo vazio, a ferramenta chama a API diretamente.
